Документация. Система управления киберспортивными турнирами

Модель данных и UML-диаграмма классов
Команда П-24-68Б: Чефранов, Восковец, Карелов.
Версия 1.0 (предварительная модель, уточняется на витке 2 вместе с ER-диаграммой).

1. Назначение документа

Документ описывает модель данных портала киберспортивных турниров: сущности, их атрибуты, связи и правила, которые модель должна поддерживать. Он основан на UML-диаграмме классов и на документе требований к сайту.

Портал заменяет Excel и чаты единым местом. Организатор создаёт турнир и сетку, капитаны подают заявки, а зрители видят расписание, счёт и трансляции без регистрации.

2. Роли пользователей
Зритель. Смотрит сетки, расписание, счёт, стримы и архив без регистрации. Ничего не меняет.
Капитан. Подаёт заявку, ведёт состав и профиль команды, видит свои матчи. Счёт и сетку не меняет.
Организатор. Создаёт турнир, строит и публикует сетку, ведёт расписание, вводит счёт. Работает только со своими турнирами.
Администратор. Управляет пользователями и ролями, модерирует, удаляет турниры. Его действия пишутся в журнал.
Система. Продвигает победителя, пересчитывает статистику, отправляет уведомления (P2). Сама результаты не вводит.

Роль выбирается при регистрации, повышение роли делает только администратор. Роль хранится в поле User.role.

4. Описание классов
4.1. User

Пользователь системы. Роль определяет права, пароль хранится только в виде хэша.

Поле	Тип	Описание
id	int	Первичный ключ
email	string	Адрес для входа, уникален, не публикуется
password_hash	string	Хэш пароля
role	string	Роль пользователя
4.2. Team

Команда. Создаётся и ведётся капитаном, состоит из игроков.

Поле	Тип	Описание
id	int	Первичный ключ
name	string	Название команды
captain_id	int	Внешний ключ на User: капитан
4.3. Player

Игрок в составе команды. Публично виден только ник.

Поле	Тип	Описание
id	int	Первичный ключ
team_id	int	Внешний ключ на Team
nickname	string	Игровой ник, уникальность проверяется при подаче заявки
4.4. Tournament

Турнир. Создаётся организатором, объединяет регистрации команд и матчи.

Поле	Тип	Описание
id	int	Первичный ключ
title	string	Название турнира
game	string	Игровая дисциплина
format	string	Формат сетки (single или double elimination)
status	string	Состояние турнира
start_at	datetime	Дата и время начала
organizer_id	int	Внешний ключ на User: организатор
4.5. Registration

Заявка команды на участие в турнире. Связывает Team и Tournament.

Поле	Тип	Описание
tournament_id	int	Внешний ключ на Tournament
team_id	int	Внешний ключ на Team
seed	int	Посев команды в сетке
status	string	Статус заявки
4.6. Match

Матч турнирной сетки. Поле next_match_id строит дерево сетки: победитель переходит в следующий матч.

Поле	Тип	Описание
id	int	Первичный ключ
tournament_id	int	Внешний ключ на Tournament
round	int	Номер раунда
slot	int	Номер слота в раунде
team_a_id	int	Первая команда
team_b_id	int	Вторая команда
start_at	datetime	Время проведения матча
next_match_id	int	Ссылка на следующий матч (самосвязь)
4.7. MatchResult

Результат матча. Не более одного результата на матч, без матча он не существует.

Поле	Тип	Описание
match_id	int	Внешний ключ на Match
score_a	int	Счёт первой команды, целое число не меньше 0
score_b	int	Счёт второй команды, целое число не меньше 0
winner_id	int	Команда-победитель
entered_by	int	Внешний ключ на User: кто ввёл счёт
4.8. Stream

Трансляция матча на внешней платформе (Twitch или YouTube).

Поле	Тип	Описание
id	int	Первичный ключ
match_id	int	Внешний ключ на Match
platform	string	Платформа трансляции
url	string	Ссылка на стрим
5. Связи между классами
User — Team, 1 — 0..*, «капитан». Пользователь может быть капитаном нескольких команд, у команды один капитан.
User — Tournament, 1 — 0..*, «организатор». Пользователь организует несколько турниров, у турнира один организатор.
Team — Player, 1 — 1..*, «состоит из». В команде минимум один игрок (для заявки по требованиям не меньше 5).
Team — Registration, 1 — 0..*, «имеет регистрации». Команда может подавать заявки на разные турниры.
Tournament — Registration, 1 — 0..*, «регистрирует». В турнире много заявок команд.
Tournament — Match, 1 — 0..*, «содержит матчи». Для N команд в сетке N − 1 матчей.
Match — Match, 0..* — 0..1, «следующий матч». Самосвязь через next_match_id, задаёт дерево сетки.
Match — MatchResult, 1 — 0..1, композиция, «имеет результат». Результат удаляется вместе с матчем.
Match — Stream, 0..* — 0..1, «имеет стрим». У матча может быть трансляция.
6. Правила и ограничения
Раунды. Число раундов равно log₂ N с округлением вверх.
Слоты и автопроходы. Число слотов равно ближайшей степени двойки, не меньшей N. Недостающие места занимают автопроходы (bye), их получают сильнейшие посевы. Пример: 11 команд, 16 слотов, 5 автопроходов (посевы 1–5).
Число матчей. N − 1 для single elimination. Для double elimination 2N − 2, плюс 1 при реванше финала.
Посев. Сильнейший играет со слабейшим: 1 против 16, 2 против 15 и так далее. До публикации сетки посев можно задать вручную.
Победитель. Команда с большим счётом. Ничья не допускается, вводится овертайм. Счёт 1:1 отклоняется с ошибкой.
Автопроход. Не считается победой в статистике.
Ввод счёта. Только организатор своего турнира и администратор, проверка на сервере. Попытка капитана заканчивается ответом 403 и записью в журнал.
Исправление счёта. Допустимо, пока следующий матч не начат. Иначе правка запрещена, нужно обратиться к администратору.
Заявка команды. Не меньше 5 игроков, ники уникальны. При превышении лимита команд заявка попадает в лист ожидания.
Приватность. E-mail игроков не публикуется, видны только ник и команда.
7. Соответствие требованиям
FR-01 Вход по e-mail, роли: User.
FR-02 Создание турнира: Tournament, User (organizer).
FR-03 Заявка команды, лист ожидания: Team, Player, Registration.
FR-04, FR-05, FR-11 Сетки и посев: Tournament, Registration (seed), Match (round, slot, next_match_id).
FR-06 Слоты матчей, время: Match (slot, start_at).
FR-07 Ввод счёта, перенос победителя: MatchResult, Match (next_match_id).
FR-08, FR-12 Публичная страница, архив: Tournament, Match, MatchResult.
FR-09 Профили и статистика: Team, Player, MatchResult.
FR-10 Встроенный стрим: Stream.
